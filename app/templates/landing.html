CORE FEATURES

Built around the gaps between your existing apps.

ArrNexus does not replace your Arr applications or media servers. It coordinates, observes and automates across them.

ARCHITECTURE

Your existing stack remains the stack.

Requests still flow through Radarr, Sonarr and Lidarr toward the providers and media libraries you already run. ArrNexus adds cross-service policy, routing, health and visibility around that workflow.

NEW IN VERSION 10

ArrNexus can now update ArrNexus.

After the one-time v10 Docker upgrade, normal application releases can be discovered from the official GitHub Releases feed, checksum-verified, backed up, validated, staged and restarted from inside ArrNexus itself.

GitHub Release→Update notification→SHA-256 verify→Database backup→Full validation→Automatic restart
No Docker socket required.The database remains under persistent /data; each application runtime is staged separately with automatic startup rollback.
QUICK START

Source, Git or Portainer — then future updates happen in-app.

Git clone + Docker Compose source build
git clone https://github.com/Fudmonk95/ArrNexus.git arrnexus
cd arrnexus
mkdir -p data
docker compose config
docker compose up -d --build
Release ZIP + validation
unzip {{ release_filename }}
cd arrnexus-v10.1
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python validate.py
deactivate
docker compose up -d --build
Portainer Git Stack

Use repository https://github.com/Fudmonk95/ArrNexus.git, reference refs/heads/main and Compose path docker-compose.yml. Keep ./data:/data persistent.

Portainer Web editor / Stack file

The included Compose file can also be pasted into Portainer's Web Editor. A future official GHCR image can use ghcr.io/<GITHUB_OWNER>/arrnexus:latest; do not assume an unofficial image is trusted.
