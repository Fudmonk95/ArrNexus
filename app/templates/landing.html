WHAT ARRNEXUS IS

The intelligence layer above your stack.

ArrNexus does not try to replace the mature applications already running your media server. It coordinates them: one place to understand what is connected, where media should go, how it should be acquired and what needs attention.

HOW IT WORKS

From deployment to a checked media stack.

1

Deploy ArrNexus

Run the Portainer/Docker stack with only persistent ./data:/data required for normal configuration.

2

Create administrator

Private pages stay behind local authentication from the first run.

3

Detect environment

Check PID namespace access, DUMB process discovery and logical mount visibility.

4

Connect services

Add Arr and ecosystem URLs/API credentials through the UI and verify them.

5

Register providers

Enable the Debrid and Usenet capabilities your installation actually uses.

6

Review readiness

See missing dependencies before trusting automated acquisition and routing.

DESIGNED FOR REAL LIBRARIES

Safety is part of the architecture.

Non-destructive by default

Language rejection and routing problems do not delete the original Debrid/DMM source.

Preview before risky changes

AIOStreams full-config writes use digest checks, masked previews, backups and rollback.

Secrets stay private

Credentials live in persistent data, are masked in UI/logs and are excluded from public release exports.

Performance-aware

Expensive namespace and dashboard state is cached/prewarmed so normal navigation does not become a storage scan.
